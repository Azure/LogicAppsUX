# Multiple Structures to One

Synthetic manual sample modeled on the reported FootballPlayers/HockeyPlayers map.
It is not the customer's original map.

- `Input.xsd`: an Input root containing a repeating choice of FootballPlayers and HockeyPlayers. Both records have Name, Gender, and Team fields.
- `AnotherOutput.xsd`: an Output root containing repeating Player records with the same three fields.
- `MapToOnlyOneStructure.btm`: both source records feed one Looping functoid (FID 424), which feeds Player. Six direct field links map both branches to the target fields.
- `input.xml`: two football players followed by two hockey players.
- `expected-output.xml`: the intended four Player records, supplied for manual comparison, not generated by executing the map.

Open the BTM with its schemas beside it, or import it into a mapper project. Verify that each source link attaches to its named record or field, not Input. The map uses BizTalk-style namespace-aware paths including the source `<Choice>` group.

Use the supplied input with Test Map and compare the result to the reference output. Each source record should produce one Player, with no fields taken from a different record and no concatenated duplicate values. Namespace prefix spelling and XML formatting need not match.

## Preserve Sequence Order

The BTM defaults to PreserveSequenceOrder="No". With the original grouped input, both No and Yes should produce Alex, Sam, Jordan, Taylor, as shown in `expected-output.xml`.

For a manual ordering comparison, use `input-interleaved.xml`, which contains football Alex, hockey Jordan, football Sam, hockey Taylor:

- With PreserveSequenceOrder="No", compare against `expected-output.xml`: Alex, Sam, Jordan, Taylor, grouped by the Looping input links.
- Set PreserveSequenceOrder="Yes" in the BTM, reopen the map, and compare against `expected-output-interleaved.xml`: Alex, Jordan, Sam, Taylor, in source document order.

These expected outputs are manual reference files, not executed transformation results. Sequence preservation does not zip separate lists by occurrence number. It preserves the order of the selected nodes in the input XML, matching the legacy mapper's sequence loop behavior.
